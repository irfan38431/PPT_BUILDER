# Codebase Concerns

**Analysis Date:** 2026-03-27

## Tech Debt

**[API Stability - Gemini Model Names]:**
- Issue: Project uses preview model names that may change without notice (`gemini-3-flash-preview`, `gemini-3-pro-preview`, `gemini-3-pro-image-preview`)
- Files: `ppt_builder/config.py` (lines 40-46), `ppt_builder/generators/nano_banana_pro.py` (line 39)
- Impact: Image generation and content generation may break if Google renames preview models
- Fix approach: Pin to stable model names when available, or add configuration fallback

**[Large Monolithic Streamlit App]:**
- Issue: `app.py` is 2608 lines with no modular separation
- Files: `ppt_builder/app.py`
- Impact: Hard to test, maintain, and extend; high coupling between UI and business logic
- Fix approach: Extract phases into separate modules under `ui/` or `pages/`

**[Hardcoded Magic Numbers]:**
- Issue: Layout dimensions and magic numbers scattered throughout generators
- Files: `ppt_builder/generators/ppt_generator.py` (lines 28-68), `ppt_builder/generators/chart_annotator.py` (lines 27-36)
- Impact: Changing slide dimensions or theme requires editing multiple locations
- Fix approach: Centralize in `config.py` or create a `LayoutConfig` dataclass

**[Deprecation Risk - PyPDF2]:**
- Issue: `requirements.txt` specifies `PyPDF2>=3.0.0` but PyPDF2 is deprecated in favor of `pypdf`
- Files: `ppt_builder/requirements.txt` (line 26)
- Impact: Security vulnerabilities may not be patched; future Python versions may break
- Fix approach: Replace with `pypdf>=4.0.0`

## Known Bugs

**[Research Data Truncation Silent Loss]:**
- Symptoms: Large presentations may have incomplete research context on later slides
- Files: `ppt_builder/agents/slide_content_agent.py` (lines 110, 135), `ppt_builder/orchestrator.py` (lines 356, 388, 457)
- Trigger: Research data passed to slide content uses `[:4000]` truncation without user notification
- Workaround: Reduce presentation complexity or increase token limits

**[Content Generation Failure Creates Placeholder Slides]:**
- Symptoms: Slides show "Content generation failed" bullet instead of actual content
- Files: `ppt_builder/agents/slide_content_agent.py` (lines 213-217)
- Trigger: LLM API errors during `generate_all()` parallel execution
- Workaround: Manual regeneration of failed slides via UI

## Security Considerations

**[API Key Exposure Risk]:**
- Risk: `.env` file contains `GEMINI_API_KEY` and potentially other secrets
- Files: `ppt_builder/config.py` (lines 36-38), `.env` (existence noted)
- Current mitigation: `.env` in `.gitignore`
- Recommendations: 
  - Use secrets manager (GCP Secret Manager, AWS Secrets Manager) in production
  - Add validation that API key format matches expected pattern
  - Implement key rotation mechanism

**[Email Credentials - Plaintext Storage]:**
- Risk: SMTP credentials passed as function parameters and potentially stored in session state
- Files: `ppt_builder/utils/email_sender.py` (lines 15-24, 58-67)
- Current mitigation: None - uses Gmail SMTP directly
- Recommendations: Use OAuth2 for Gmail, encrypt credentials at rest

**[File Upload - No Content Validation]:**
- Risk: User-uploaded files (Excel, CSV, audio, video, PDF) processed without sandboxing
- Files: `ppt_builder/agents/transcript_agent.py`, `ppt_builder/agents/data_analysis_agent.py`, `ppt_builder/agents/url_research_agent.py`
- Current mitigation: File size limit (20MB default), file type checking by extension
- Recommendations: Add MIME type validation, virus scanning for uploads, sandbox file processing

**[SQL Injection via LLM-Generated Queries]:**
- Risk: DuckDB queries generated by LLM (`query_agent.py`) could contain malicious SQL
- Files: `ppt_builder/db/duckdb_local.py` (line 104), `ppt_builder/agents/query_agent.py`
- Current mitigation: Column names sanitized via `_sanitize_column_names()`; DuckDB in-memory only
- Recommendations: Implement query validation layer, restrict DuckDB permissions

## Performance Bottlenecks

**[Synchronous Pipeline in Streamlit]:**
- Problem: Pipeline phases execute synchronously, blocking the Streamlit UI
- Files: `ppt_builder/app.py` (various phase functions), `ppt_builder/orchestrator.py`
- Cause: No async/await patterns; ThreadPoolExecutor used but not for HTTP operations
- Improvement path: Convert to async operations, use Streamlit's `st.fragment` for incremental updates

**[Memory Pressure from Large Files]:**
- Problem: Excel files loaded entirely into memory via pandas, then DuckDB
- Files: `ppt_builder/db/duckdb_local.py` (line 56), `ppt_builder/agents/data_table_engine.py` (line 126)
- Cause: No streaming/chunked processing for large datasets
- Improvement path: Process Excel files in chunks, use DuckDB's streaming capabilities

**[PNG Preview Generation Per Slide]:**
- Problem: Every slide generates a matplotlib preview PNG for refinement
- Files: `ppt_builder/generators/slide_previewer.py`, `ppt_builder/orchestrator.py` (lines 1076-1078)
- Cause: Preview renders created even when refinement may fail
- Improvement path: Lazy generation, cache previews, skip for data-heavy slides

## Fragile Areas

**[LLM JSON Parsing - Strict Validation]:**
- Files: `ppt_builder/engine/llm_provider.py` (lines 131-140)
- Why fragile: Any deviation from expected schema causes `ValueError`; no recovery attempt
- Safe modification: Add retry with prompt refinement on parse failure
- Test coverage: None

**[DuckDB Local Connector Lifecycle]:**
- Files: `ppt_builder/db/duckdb_local.py` (lines 40, 106-111)
- Why fragile: Connection managed via `close()` but `__exit__` relies on caller calling it
- Safe modification: Use context manager pattern consistently
- Test coverage: None

**[ThreadPoolExecutor Worker Count Magic Numbers]:**
- Files: `ppt_builder/orchestrator.py` (workers: 4, 6, 8)
- Why fragile: Hardcoded worker counts may saturate API rate limits
- Safe modification: Make configurable, respect Gemini API quotas

## Scaling Limits

**[Streamlit Session State]:**
- Current capacity: All pipeline state stored in `st.session_state`
- Limit: Memory-bound; large presentations (50+ slides) may hit memory limits
- Scaling path: Persist state to database, use incremental loading

**[In-Memory DuckDB]:**
- Current capacity: Limited by available RAM; one file at a time
- Limit: Large Excel files (hundreds of MBs) may cause OOM
- Scaling path: Use disk-backed DuckDB, process in batches

**[API Rate Limits]:**
- Current capacity: No explicit rate limiting
- Limit: Gemini API quotas (varies by tier)
- Scaling path: Implement exponential backoff, queue system for batch jobs

## Dependencies at Risk

**[google-genai SDK - Preview Models]:**
- Risk: Preview model names may change or be deprecated
- Impact: `generate_visual()` and content generation break
- Migration plan: Monitor Google AI changelog, create alias mapping for model names

**[matplotlib Version Compatibility]:**
- Risk: Global style settings in `chart_annotator.py` affect all matplotlib usage
- Impact: Version updates may change default behaviors
- Migration plan: Use explicit style contexts, test with newer matplotlib versions

## Missing Critical Features

**[Error Recovery/Retry]:**
- Problem: Single LLM failures cascade to pipeline failure without recovery
- Blocks: Production use with unreliable API connections

**[Input Validation Layer]:**
- Problem: User inputs (URLs, topics, file types) not validated before processing
- Blocks: Security hardening, reliable automation

**[Configuration for Non-Defaults]:**
- Problem: Many behaviors hardcoded (worker counts, thresholds, buffer sizes)
- Blocks: Multi-tenant deployment, performance tuning
